This guide covers some common steps with the setup of WSL2.

Once some of the common issues with WSL2 are addressed, you should be able to follow [this local setup guide](/how-to-setup-freecodecamp-locally/) to work with freeCodeCamp on Windows running a WSL distro like Ubuntu.

<Aside type='note'>

Before you follow these instructions make sure your system meets the requirements.

</Aside>

<Card title='System Requirements' icon='laptop'>

- **Hardware**:
  - A fast CPU (6+ cores)
  - At least 12+ GB RAM
  - 20+ GB of free disk space
  - (Optional) 30-50 Mbps internet connection
- **Operating System**: A supported 64-bit version of Windows that meets the [Docker Desktop system requirements](https://docs.docker.com/desktop/setup/install/windows-install/#system-requirements). The minimum Windows version for installing WSL alone is not sufficient for Docker Desktop.
- **WSL**: Version 2.1.5 or later, with your Linux distribution running in WSL 2 mode.
- **Docker Desktop for Windows**: See [the installation instructions](https://docs.docker.com/desktop/setup/install/windows-install/).

</Card>

## Enable WSL

Follow the instructions on the [official documentation](https://docs.microsoft.com/en-us/windows/wsl/install-win10) to install WSL2.

## Install Ubuntu

<Steps>

1. We recommend using an Ubuntu LTS release supported by [Playwright](https://playwright.dev/docs/intro#system-requirements), such as Ubuntu 24.04, with WSL2.

   Playwright, the end-to-end testing library used by freeCodeCamp, supports specific Ubuntu and Debian releases. Check its system requirements before choosing a release.

   You may use other non-Debian-based distributions, they all come with their own 'gotchas' that are beyond the scope of this guide.

   Here is how you can [run a linux flavour](https://learn.microsoft.com/en-us/windows/wsl/install#ways-to-run-multiple-linux-distributions-with-wsl) of your choice

2. Update the dependencies for the OS

   ```bash
   sudo apt update
   sudo apt upgrade -y

   # cleanup
   sudo apt autoremove -y
   ```

</Steps>

## Set up Git

Check that Git is installed in your Ubuntu distribution:

```bash
git --version
```

If Git is not installed, run `sudo apt install git`.

(Optional but recommended) You can now proceed to [setting up your ssh keys](https://help.github.com/articles/generating-an-ssh-key) with GitHub.

## Installing a Code Editor

Install [Visual Studio Code](https://code.visualstudio.com) on Windows and install its [WSL extension](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-wsl). Open your project folder from an Ubuntu terminal with `code .`, or use **WSL: Connect to WSL** from the VS Code Command Palette.

VS Code installs its server in WSL when you first connect. Other extensions may need to be installed in WSL separately; see the [VS Code instructions for managing extensions](https://code.visualstudio.com/docs/remote/wsl#_managing-extensions).

**You will edit and store your code in your Ubuntu distribution, with VS Code installed on Windows.**

## Installing Docker Desktop

**Docker Desktop for Windows** allows you to install and run databases like MongoDB and other services like NGINX and more. This is useful to avoid common pitfalls with installing MongoDB or other services directly on Windows or WSL2.

Follow the instructions on the [official documentation](https://docs.docker.com/docker-for-windows/install) and install Docker Desktop for your Windows distribution.

## Configure Docker Desktop for WSL

Once Docker Desktop is installed, [enable its WSL 2 backend](https://docs.docker.com/desktop/features/wsl/). In **Settings > Resources > WSL Integration**, enable integration for your Ubuntu distribution and apply the changes.

Docker Desktop runs in its own `docker-desktop` WSL distribution. Integration lets you use Docker commands from your Ubuntu terminal. Services with published ports can be accessed through `localhost` on Windows and Ubuntu.

## Installing Node.js and pnpm

We recommend you install the LTS release for Node.js with [node version manager - `nvm`](https://github.com/nvm-sh/nvm#installing-and-updating). Once installed use this command to install and use the latest Node.js LTS version:

```bash
nvm install --lts
```

For instructions on installing and using a different version of Node.js, please refer to the [nvm docs](https://github.com/nvm-sh/nvm#usage).

Node.js comes bundled with `npm`, which you can use to install `pnpm`:

```bash
npm install -g pnpm
```

## Optimize memory allocation

The default settings for your WSL installation can vary, we recommend tuning the memory allocated to WSL by Windows by following these steps.

Create a `.wslconfig` file in your `%UserProfile%` directory, typically at `C:\Users\<UserName>\.wslconfig`. Replace `x` with values that suit your own needs:

```ini
# Settings apply across all Linux distros running on WSL 2
[wsl2]
# Memory to assign to the WSL 2 VMs.
memory=xGB
# Swap space (on disk) for the WSL 2 VMs, default is 25% of available RAM
swap=xGB
```

Save your work and stop running workloads before applying these settings. Run the following command from PowerShell to shut down all WSL distributions:

```powershell
wsl --shutdown
```

Restart your Ubuntu distribution and Docker Desktop for the new settings to take effect.

You can read more about the config in the [official guide here](https://learn.microsoft.com/en-us/windows/wsl/wsl-config).
