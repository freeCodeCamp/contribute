This guide sets up a development environment for freeCodeCamp. Work through it once, in order.

<Aside type='danger' title='Warning for Windows Users'>

## Fork the freeCodeCamp repository on GitHub

A [fork](https://help.github.com/articles/about-forks) is your own copy of the codebase. You need one to contribute.

<Steps>

1. Open the fork page:

   <LinkButton
     href='https://github.com/freeCodeCamp/freeCodeCamp/fork'
     icon='seti:github'
     iconPlacement='start'
     variant='secondary'
     target='_blank'
   >
     Fork freeCodeCamp
   </LinkButton>

2. Check the details, then click **Create fork**.

3. GitHub redirects you to your fork at `https://github.com/YOUR_USER_NAME/freeCodeCamp`.

</Steps>

In this guide, `origin` means your fork and `upstream` means the main repository. You can delete your fork at any time and start again.

## Choose where to run freeCodeCamp

There are three ways to run the project. All three work. Compare them, pick one, then follow that tab. The tabs here and in the next section stay in step, so your choice carries through.

|                              | Local Machine                      | Dev Container                                                                  | GitHub Codespaces                                                  |
| ---------------------------- | ---------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| **Where it runs**            | Directly on your machine           | In Docker, on your machine                                                     | On a GitHub server                                                 |
| **You install**              | Node.js, pnpm, Docker Compose, Git | Docker Desktop, VS Code, Dev Containers extension, Git                         | Nothing                                                            |
| **You manage tool versions** | Yes                                | No. The image carries them                                                     | No. The image carries them                                         |
| **Machine needed**           | 4 CPUs, 8 GB of RAM, 10 GB of disk | 4 CPUs and 16 GB of RAM given to Docker, plus your own operating system on top | A 4-core, 16 GB, 32 GB disk machine. The project sets this minimum |
| **Speed**                    | Fastest                            | Slower file access on macOS and Windows                                        | Depends on your connection                                         |
| **Works offline**            | Yes, after setup                   | Yes, after the first start                                                     | No                                                                 |
| **Cost**                     | Free                               | Free                                                                           | A free monthly quota, then paid                                    |

<Aside type='note'>

Each option gives you the same running application. Pick the one that fits your machine and how often you plan to contribute.

</Aside>

#### Prerequisites

Your machine needs 4 CPU cores, 8 GB of RAM and 10 GB of free disk space, on macOS or Linux. On Windows, use WSL2 and expect to need more of each.

| Prerequisite                                                                                  | Version | Notes                                                                                         |
| --------------------------------------------------------------------------------------------- | ------- | --------------------------------------------------------------------------------------------- |
| [Git](https://git-scm.com/)                                                                   | latest  | The version bundled with your operating system is often outdated.                             |
| [Node.js](http://nodejs.org)                                                                  | `24.x`  | The "Active LTS" version. See the [LTS schedule](https://nodejs.org/en/about/releases/).      |
| [pnpm](https://pnpm.io/installation)                                                          | `10.x`  | -                                                                                             |
| [Docker Compose](https://docs.docker.com/compose/install/)                                    | `2.x`   | Starts MongoDB for you in Step 3.                                                             |
| [MongoDB Community Server](https://docs.mongodb.com/manual/administration/install-community/) | `8.x`   | Optional. Only if you prefer to run MongoDB without Docker. The Docker path runs `mongo:8.2`. |

Check what you have:

```bash
node -v && pnpm -v
```

<Aside type='caution' title='Versions matter'>

A version other than the one listed is the most common cause of a failed setup. See [troubleshooting](/troubleshooting-development-issues/).

</Aside>

Recommended, but not required:

- [Set up an SSH key](https://help.github.com/articles/generating-an-ssh-key/) for GitHub.
- Use a code editor. [Visual Studio Code](https://code.visualstudio.com/) is free and open source.
- Run [ESLint in your editor](http://eslint.org/docs/user-guide/integrations.html). It flags anything that breaks [freeCodeCamp's JavaScript Style Guide](http://forum.freecodecamp.org/t/free-code-camp-javascript-style-guide/19121). Do not ignore its errors.

#### Clone your fork

<Steps>

1. Clone your fork, replacing `YOUR_USER_NAME` with your GitHub username:

   ```bash
   git clone --depth=1 https://github.com/YOUR_USER_NAME/freeCodeCamp.git
   cd freeCodeCamp
   ```

   `--depth=1` fetches only the most recent commit, which keeps the download small.

2. Add a remote that points at the main repository, so that you can sync later:

   ```bash
   git remote add upstream https://github.com/freeCodeCamp/freeCodeCamp.git
   ```

   Run `git remote -v` to confirm. You should see `origin` on your fork and `upstream` on `freeCodeCamp/freeCodeCamp`.

3. **(Optional)** To work on a localized curriculum, fetch the [i18n-curriculum](https://github.com/freeCodeCamp/i18n-curriculum) submodule:

   ```bash
   git submodule update --init
   ```

</Steps>

</TabItem>

<TabItem label="Dev Container" icon="seti:config">

A dev container runs the same image that GitHub Codespaces uses, on your own machine. You install Docker and VS Code, and the container carries Node.js, pnpm, MongoDB and every dependency.

#### Dev Container prerequisites

| Prerequisite                                                                                                       | Notes                                    |
| ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------- |
| [Git](https://git-scm.com/)                                                                                        | -                                        |
| [Docker Desktop](https://docs.docker.com/get-started/get-docker/)                                                  | Any Docker Engine with Compose v2 works. |
| [Visual Studio Code](https://code.visualstudio.com/)                                                               | -                                        |
| [Dev Containers extension](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-containers) | -                                        |

In Docker's resource settings, give it at least 4 CPUs and 16 GB of memory.

The client build alone asks for a 7 GB JavaScript heap, and Docker treats its memory setting as a hard limit, so less than that stops the build with no clear error. Docker uses this on top of what your operating system needs, so this option asks more of your machine than a direct install does.

#### Open the project in a container

<Steps>

1. Clone your fork, replacing `YOUR_USER_NAME` with your GitHub username:

   ```bash
   git clone --depth=1 https://github.com/YOUR_USER_NAME/freeCodeCamp.git
   ```

2. Change into the new directory:

   ```bash
   cd freeCodeCamp
   ```

3. Add a remote reference to the main repository, so that you can sync later:

   ```bash
   git remote add upstream https://github.com/freeCodeCamp/freeCodeCamp.git
   ```

   **(Optional)** To work on a localized curriculum, also fetch the [i18n-curriculum](https://github.com/freeCodeCamp/i18n-curriculum) submodule:

   ```bash
   git submodule update --init
   ```

4. Open the folder in VS Code:

   ```bash
   code .
   ```

5. Open the Command Palette (`Ctrl+Shift+P` / `Cmd+Shift+P`), then select **Dev Containers: Reopen in Container**.

6. Wait for the setup to finish. The terminal shows `Done. Press any key to close the terminal.`

</Steps>

The container installs the dependencies, writes `.env`, starts MongoDB and Mailpit, and seeds the database. You do none of that by hand.

<Aside type='note' title='The first start is slow'>

The first start downloads a prebuilt image of several gigabytes. Later starts are fast.

</Aside>

</TabItem>

<TabItem label="GitHub Codespaces" icon="seti:github">

A codespace runs the project on a GitHub server. You install nothing, and you work in your browser or in VS Code.

**Launch a codespace from your fork:**

<Steps>

1. Go to your fork at `https://github.com/YOUR_USER_NAME/freeCodeCamp`

2. Click the green **Code** button

3. Select the **Codespaces** tab

4. Click **Create codespace on main**

   Pick the **4-core, 16 GB RAM** machine, or a larger one. The repository sets this as the minimum, so smaller machines do not appear.

   The codespace then sets itself up. It installs every dependency, starts MongoDB and Mailpit, seeds a test user, writes `.env`, and installs the ESLint and Prettier extensions.

5. Wait for the setup to finish. The creation log stops, and you get a shell prompt.

</Steps>

<Aside type='note' title='Why the URLs change'>

A browser tab inside a codespace cannot reach `localhost`. That address points at your own machine, not at the codespace. The container therefore rewrites both URLs to the forwarded `*.app.github.dev` addresses, so that the client can reach the API.

</Aside>

</TabItem>
</Tabs>

## Running freeCodeCamp

Start the application to preview your edits, work on the user interface, and debug the servers.

<Tabs syncKey="setup-environment">
<TabItem label="Local Machine" icon="laptop">

### Step 1: Create your environment file

```bash
cp sample.env .env
```

The defaults run the app as it is. Change them only if you want your own Auth0, Algolia or Stripe keys.

### Step 2: Install dependencies

```bash
pnpm install
```

<Aside type='note' title='WSL users'>

Run `pnpm run playwright:install-build-tools` first. It installs the system packages that Playwright and Puppeteer need, and may ask for your `sudo` password.

</Aside>

### Step 3: Start MongoDB and seed the database

<Steps>

1. Stop any MongoDB server already using port 27017. Skip this step and the next one if you already run a replica set there.

2. Start MongoDB as a replica set:

   ```bash
   docker compose -f docker/docker-compose.yml -f docker/docker-compose.ports.yml up -d
   ```

   This also starts Mailpit, which catches outgoing email at `http://localhost:8025`.

3. Seed the database:

   ```bash
   pnpm run seed
   ```

   This creates a test user with no completed certifications, which is enough to get started. For a user with certifications, run `pnpm run seed:certified-user` instead, then clear your browser cookies and sign in again.

</Steps>

<Aside type='note' title='Using your own MongoDB'>

If you run MongoDB outside Docker, point `MONGOHQ_URL` in `.env` at it. It must be a replica set.

</Aside>

### Step 4: Start the client and the API

```bash
pnpm run develop
```

A full curriculum build takes several minutes. Open `http://localhost:8000` when it finishes.

**Some notes:**

- The API serves endpoints at `http://localhost:3000`, and the API docs at `http://localhost:3000/documentation`.
- Mailpit catches every outgoing email at `http://localhost:8025`.

**Working on curriculum content?** Build only the part you need. It is far faster:

```bash
FCC_SUPERBLOCK='responsive-web-design' pnpm run develop
```

See [Quick Commands Reference](#quick-commands-reference) for `FCC_BLOCK` and `FCC_CHALLENGE_ID`.

<Aside type='tip' title="Congratulations - you're all set!">

freeCodeCamp's learning platform now runs on your machine. If anything failed, see [troubleshooting](/troubleshooting-development-issues/).

</Aside>

</TabItem>

<TabItem label="GitHub Codespaces" icon="seti:github">

Your codespace already installed every dependency, started the database, and seeded a test user. Start developing immediately.

<Steps>

1. Open the Command Palette (`Ctrl+Shift+P` / `Cmd+Shift+P`), type `Run Task`, then select **Start freeCodeCamp**. Or open a terminal and run:

   ```bash
   pnpm run develop
   ```

   This starts the API server and the client application.

2. Wait for the build. It takes several minutes the first time. VS Code shows a notification for port `8000` when the client is ready.

3. Open that notification to view the client in a new browser tab.

</Steps>

<Aside type='caution' title='Port 3000 must be public'>

The client calls the API from your browser, across two different forwarded origins. A private port answers that call with a GitHub sign-in redirect, and the browser reports it as a CORS error.

The container sets this on every start, including after you stop and resume the codespace, because a codespace resets port visibility each time it stops. If port `3000` is still private, open the **Ports** panel, right click port `3000`, then choose **Port Visibility > Public**.

Leave port `8000` private. A browser tab that you open yourself carries your GitHub session, so the client loads from a private port. Only the API needs a public one, because the client fetches it as a subresource.

A public port is reachable by anybody who has the URL. `sample.env` sets `FCC_ENABLE_DEV_LOGIN_MODE=true`, which serves a sign-in route that needs no password. Your codespace holds only seeded test data, but stop the codespace when you finish working.

</Aside>

**Some notes:**

- The API serves endpoints on port `3000`, and the API docs at `/documentation`.
- Mailpit catches every outgoing email on port `8025`. Open it from the **Ports** panel.

**Working on curriculum content?** Build only the part you need. It is far faster:

```bash
FCC_SUPERBLOCK='responsive-web-design' pnpm run develop
```

## Quick Commands Reference

<Card title='Handy Scripts to use locally' icon='open-book'>

| Command                                                      | Description                                                                                                   |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| `pnpm install`                                               | Installs / re-installs all dependencies and bootstraps the different services.                                |
| `pnpm run seed`                                              | Creates authorized test users and inserts them into MongoDB. Also runs `seed:exams` and `seed:surveys` below. |
| `pnpm run seed:certified-user`                               | Creates authorized test users with certifications fully completed, and inserts them into MongoDB.             |
| `pnpm run seed:exams`                                        | Creates exams and inserts them into MongoDB.                                                                  |
| `pnpm run seed:surveys`                                      | Creates surveys for default users and inserts them into MongoDB.                                              |
| `FCC_SUPERBLOCK='responsive-web-design' pnpm run develop`    | Starts the API Server and Client, building only the specified SuperBlock (recommended for curriculum work).   |
| `FCC_BLOCK='basic-html-and-html5' pnpm run develop`          | Starts the API Server and Client, building only the specified Block (recommended for curriculum work).        |
| `FCC_CHALLENGE_ID=646cf6cbca98e258da65c979 pnpm run develop` | Starts the API Server and Client, building only the specified Challenge (recommended for curriculum work).    |
| `pnpm run develop`                                           | Starts the freeCodeCamp API Server and Client Applications with full curriculum build (for thorough testing). |
| `pnpm run clean`                                             | Uninstalls all dependencies and cleans up caches.                                                             |

</Card>
